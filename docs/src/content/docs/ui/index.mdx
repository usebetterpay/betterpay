## Why a UI package

Billing UI is deceptively hard: interval toggles, status vocabulary, IDR formatting, empty states, and accessible dialogs. This package gives you production patterns that match BetterPay's domain model without owning checkout — payment links still come from Midtrans Snap, Xendit, and friends.

## Principles

- **IDR-first** — default locale `id-ID`, tabular money via `formatMoney`
- **Domain status** — `scheduled` · `active` · `past_due` · `canceled` · `ended`
- **Base UI + base-nova** — `render` composition, not Radix `asChild`
- **Presentational** — props in, callbacks out
- **Composable** — `PlanCard` / `PlanGroup` plus opinionated sections

## Install

**Option A — package (recommended for apps using the monorepo):**

```bash title="Terminal"
pnpm add @betterpay/ui
```

**Option B — shadcn registry (copy source into your app):**

```bash title="Terminal"
npx shadcn@latest add https://betterpay-docs.pages.dev/r/pricing-table.json
```

Registry index: [https://betterpay-docs.pages.dev/r/index.json](https://betterpay-docs.pages.dev/r/index.json)

```ts title="Optional theme CSS"
import '@betterpay/ui/styles.css';
```

Host apps should provide Tailwind (or equivalent) for utility classes.
